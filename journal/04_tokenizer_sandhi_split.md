# TamilBERT v1.0 — Sandhi Aware Splitting

Tamil words often blend into the word next to them through sound change rules called sandhi. A plain split on whitespace or punctuation misses this entirely, so this experiment tries to mark those natural boundaries directly, before the tokenizer ever sees the text.

## What sandhi split is

Sandhi split is a way of marking boundaries at the points where Tamil's phonological rules predict a natural word or morpheme join, without changing the underlying text in any way. The text itself stays exactly as it was; only a marker gets added to show the tokenizer where a meaningful split could go.

## Why a custom class did not work

The first attempt at building this was a custom `PreTokenizer` class written in Python, inheriting from the library's base class. It worked, but it was too slow to be practical. Every other pre-tokenizer in this project runs as compiled Rust code, and a pure Python class simply couldn't keep up once it had to run across the full corpus.

The fix used instead skips a custom pre-tokenizer entirely:

1. Generate new train and test files where the sandhi split has already been simulated ahead of time, using a special marker (⟂) to mark each boundary directly in the text.
2. Train the tokenizer on this pre-marked file and measure the fertility metric against it, just like any other setup.
3. Add one extra step to the decoder that filters this marker back out, so decoded text reads normally again with no trace of it left behind.

This precomputation step lives in `sandhi_precompute.py`.

## The sandhi rules used

The rules are built in two tiers. `TA_RULES_CORE` covers vowel joins, glide insertion, the general "consonant plus vowel automatically joins" rule, a handful of closed word lists (direction words, single-mora roots, common demonstratives), and case-suffix or verbal-participle joins. These are all high precision, meaning they rarely fire inside an ordinary word that isn't actually a compound. `TA_RULES_AGGRESSIVE` adds nasal-plus-stop clusters and consonant doubling, which are real sandhi patterns too, but the exact same letter patterns also show up natively inside single, non-compound Tamil words (அன்பு, பள்ளி, நல்ல, வெள்ளை), so including that tier means accepting a lot of false positives. This project only uses `TA_RULES_CORE`.

The rules themselves are adapted from நன்னூல் எழுத்ததிகாரம் (இயல் 3, உயிரீற்றுப் புணரியல்), cross-checked against Tamil Virtual Academy's sandhi lesson and a sutra-by-sutra blog series. A large part of நன்னூல்'s sandhi chapter depends on knowing a word's grammatical category (is it an imperative verb, a vocative, a numeral other than எட்டு/பத்து), which a plain regex over characters has no way of knowing. Those sutras are intentionally left out. What's added is genuine surface-level phonological cues, plus a few closed, finite word lists that are safe to hard-code.

Whitespace itself is treated as a separate, already existing boundary mechanism. Every space already marks a natural split, so the sandhi rules only add extra boundaries inside spans of text that would otherwise be treated as one unsplit run of characters, for example the space in அம்மா வீட்டில் is already a boundary on its own, without needing any sandhi rule to mark it.

## How boundary marking works, step by step

1. The raw Tamil text is scanned against the `TA_RULES_CORE` rules listed above. Nothing gets changed at this stage, the scan only looks for matches.
2. Each match records a single position: the point right before the second half of the match. This is called a cut point.
3. All cut points get collected into a set, which automatically removes any duplicates.
4. Cut points sitting at the very start or very end of the text are dropped, since marking a boundary there wouldn't do anything.
5. If no cut points remain after that, the text is returned exactly as it was, with no marker added.
6. If cut points do exist, the text gets sliced at each one, moving left to right, and the marker ⟂ is inserted between each slice.
7. The result is the original text with ⟂ inserted at every sandhi boundary. Nothing else about the text is touched or reordered.
8. Because ⟂ is only ever inserted and never replaces anything, stripping all the ⟂ symbols back out afterward returns the exact original text, with no information lost.
9. This marked version, the original text plus its ⟂ symbols, is what gets fed into the tokenizer training scripts, so the tokenizer can learn to treat these points as meaningful places to split.

This logic lives in `sandhi.py`.

## Why the rules changed

The first version of the sandhi rules was adapted from Aagathiyam: Sandhi aware tokenization for Tamil. It got the pipeline working end to end, but testing showed it wasn't catching enough of the joins that actually show up in real Tamil text, and it also carried a bug that hurt precision. Rather than patch it piece by piece, the rules were rebuilt from scratch for this version, cross-checked directly against நன்னூல் எழுத்ததிகாரம் and Tamil Virtual Academy's course material instead of a single existing implementation.

The rewrite added coverage the first version was missing entirely, closed lists for direction words, single-mora roots, and common demonstratives among them, and it also fixed a real bug. The old rules matched an optional whitespace (\s*) inside the pattern itself, which meant a boundary marker could get inserted across a plain space that had nothing to do with sandhi. Removing that fixed the false positives, and the regenerated files now only contain the boundaries the rules were actually meant to catch.

These regenerated files, built with the rules described above, are also the starting point for the fourth experiment, sandhi plus grapheme splitting, covered next.
